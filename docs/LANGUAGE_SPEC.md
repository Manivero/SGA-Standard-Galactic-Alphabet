# LANGUAGE SPEC — SGA Programming Language v0.1

## 1. Философия (≤20 строк)

SGA — минималистичный, статически разбираемый язык с синтаксисом на
основе SGA-кодированных ключевых слов и **градуальной** статической
типизацией (полностью опциональные аннотации — без них поведение
динамическое, см. §8). Цели: предсказуемость (никаких скрытых
преобразований типов в арифметике между несовместимыми типами),
безопасность по умолчанию (immutable `let`, Ownership/Borrowing на
границе вызова функции — §5.1, управляемые runtime-ошибки вместо
UB/паник), компактный набор конструкций без тяжёлого наследования
(`struct` вместо классовых иерархий — см. §6). Сценарии использования v0.1: обучающие программы, скрипты с
арифметикой/циклами/рекурсией/массивами/замыканиями, многофайловые
программы через `IMPORT` (§9), демонстрация архитектуры компилятора.
Преимущества: маленький, понятный исходный код компилятора, реальные
safety-проверки. Ограничения v0.1: нет enum/map/set/tuple/
optional (`struct` — есть, см. §6), нет async/threads, нет нативной
компиляции (только VM), нет полноценного borrow-checker для замыканий
(захват окружения — по значению, см. §5.2).

## 3. Переменные

```
let x = 5;        // immutable — повторное присваивание = ошибка компиляции
const y = 10;      // immutable, синоним let в v0.1
var z = 0;         // mutable
z = z + 1;         // OK
```

### Глубокая, а не "shallow", неизменяемость для коллекций

`let`/`const` в SGA — это **глубокая** неизменяемость (как в Rust/Swift),
а не только защита привязки имени (как `const` в JS или `val` в Kotlin,
где массив всё равно можно мутировать по индексу). Поэтому:

```
let arr = [1, 2, 3];
arr[0] = 99;      // ОШИБКА КОМПИЛЯЦИИ: нельзя мутировать через LET
push(arr, 4);     // ОШИБКА КОМПИЛЯЦИИ: то же самое

var arr2 = [1, 2, 3];
arr2[0] = 99;     // OK — VAR разрешает мутацию
```

Выбор сделан в пользу более сильной гарантии (Rust — основное заявленное
вдохновение проекта, и `docs/SECURITY.md` заявляет "immutable by
default" как свойство безопасности, а не просто стиль). Реализация —
`src/semantic/mod.rs::check_mutation_target`.

**Граница вызова функции ЗАКРЫТА в v0.1 через Ownership/Borrowing** (см.
§5.1 ниже) — параметры функций по умолчанию immutable, мутация снаружи
требует явного `MUT` на параметре и `VAR` на месте вызова. До этого
(в более раннем раунде разработки) здесь была реальная дыра: параметры
были всегда мутабельны независимо от объявления аргумента — она найдена,
задокументирована и закрыта, см. `docs/SECURITY.md`.

## 4. Управление потоком

```
if cond { ... } else if cond2 { ... } else { ... }

while cond { ... }

for i in 0..10 { ... }   // полуоткрытый диапазон [0, 10)

break;
continue;
```

`match` — запланирован, не реализован в v0.1 (см. ROADMAP).

## 5. Функции

```
fn add(a, b) {
    return a + b;
}
print(add(2, 3));
```

Обычные функции — только верхнего уровня (вложенные `FN имя(...)`
запрещены парсером, см. §9 о грамматике). Анонимные функции/замыкания —
см. §5.2 ниже.

## 5.1. Ownership/Borrowing

Параметр функции без аннотации — **immutable-заимствование**: тело
функции может читать значение, но не может ни переприсвоить имя
параметра, ни мутировать его содержимое (`arr[i] = v`, `push(arr, v)`).
Это проверяется тем же механизмом, что и `LET`-переменные.

```
fn read_only(arr) {
    return arr[0];   // OK — чтение разрешено
}

fn broken(arr) {
    arr[0] = 99;      // ОШИБКА КОМПИЛЯЦИИ: arr — immutable-заимствование
}
```

`MUT` перед параметром делает его **mutable-заимствованием**: тело
функции может мутировать содержимое, и эта мутация видна вызывающей
стороне (общий `Rc<RefCell<...>>` буфер массива). Но тогда аргумент на
месте вызова обязан сам быть `VAR`-связанным — передать `LET`-переменную
в `MUT`-параметр — ошибка компиляции (borrow-checking на месте вызова).

```
fn mutate(mut arr) {
    arr[0] = 99;      // OK — arr объявлен с MUT
}

var data = [1, 2, 3];
mutate(data);          // OK — data объявлена через VAR
print(data);            // [99, 2, 3] — мутация видна снаружи

let frozen = [1, 2, 3];
mutate(frozen);         // ОШИБКА КОМПИЛЯЦИИ: frozen — LET, а параметр MUT
```

Это явный, видимый в сигнатуре функции контракт (как `&mut` в Rust),
а не скрытое поведение — в отличие от более раннего состояния проекта,
где параметры были всегда мутабельны независимо от объявления (см.
`docs/ROADMAP.md`, история закрытия этой дыры). Реализация —
`src/semantic/mod.rs::check_call_borrows` (проверка на месте вызова) и
`declare(&p.name, p.mutable)` в обработке `FnDecl` (проверка внутри тела).

**Не реализовано** (см. ROADMAP): несколько одновременных
заимствований одной переменной, времена жизни (lifetimes), заимствование
полей структур (структур пока нет), заимствование элементов массива
по отдельности (`&mut arr[0]`).

## 5.2. Замыкания

`FN(параметры) { тело }` БЕЗ имени — выражение, а не statement: создаёт
значение типа `closure`, которое можно сохранить в переменную, передать
аргументом, вызвать сразу (IIFE) или вернуть из другой функции.

```
let add = FN(a, b) { return a + b; };
print(add(2, 3));                      // 5

print(FN(x) { return x * 2; }(21));    // 42 — немедленный вызов (IIFE)

fn make_adder(n) {
    return FN(y) { return n + y; };    // захват n по значению
}
let add5 = make_adder(5);
print(add5(1));                        // 6
```

**Захват — по значению, не по ссылке**: в момент создания замыкания
снимается копия всех видимых переменных (вместе с их флагом
mutable/immutable). Последующее изменение переменной снаружи НЕ видно
внутри уже созданного замыкания:

```
var counter = 1;
let read_it = FN() { return counter; };
counter = 99;
print(read_it());   // 1, а не 99 — захвачено в момент создания FN(...)
```

Присваивание захваченной `LET`-переменной внутри тела замыкания остаётся
ошибкой компиляции, как и для любого другого immutable-имени. Параметры
самого замыкания (в отличие от параметров top-level `FN имя(...)`, см.
§5.1) не принимают `MUT`/аннотации типов — упрощение v0.1, см. ROADMAP.
`MUT`-параметры top-level функций и замыкания свободно сочетаются в
одной программе — это не взаимоисключающие фичи.

**Не реализовано** (см. ROADMAP): mutable upvalues (захват по ссылке),
borrow-checking для захваченных переменных, типизированные сигнатуры
замыканий (`closure(int) -> int`, а не просто `closure`).

## 6. ООП: структуры (`STRUCT`)

> Перенесено и интегрировано при слиянии веток — см.
> `docs/MIGRATION_REPORT.md`. `interface`/`trait`/наследование — НЕ
> реализованы (осознанное архитектурное решение, согласовано с
> философией языка, см. §1) и остаются зарезервированными словами без
> семантики (см. ROADMAP).

`STRUCT` объявляет номинальный тип-запись — именованную коллекцию
полей без аннотаций типов (поля не участвуют в градуальной системе
типов §7 — типизируются как `any`). Только на верхнем уровне программы,
как `FN` и `IMPORT`.

```
struct Point {
    x, y
}

let p = Point { x: 3, y: 4 };
print(p.x + p.y);            // 7
```

Экземпляр struct — **reference-тип**, как и массив (§2): присваивание
переменной не копирует поля, обе переменные ссылаются на один объект.

```
var a = Point { x: 1, y: 1 };
var b = a;
b.x = 99;
print(a.x);                  // 99 — a и b — один объект
```

Поэтому присваивание полю (`p.x = ...`) подчиняется тем же правилам
Ownership/Borrowing (§5.1), что и индексное присваивание массива:
запрещено через переменную, объявленную `LET`/`CONST`.

```
let frozen = Point { x: 0, y: 0 };
frozen.x = 1;                 // ОШИБКА КОМПИЛЯЦИИ: frozen — immutable
```

### Методы

Нет синтаксиса `impl`. Метод — обычный top-level `FN` с именем по
конвенции `TypeName_method(self, ...)`; вызывается через `.`:

```
fn Point_move(mut self, dx, dy) {
    self.x = self.x + dx;
    self.y = self.y + dy;
}

p.move(1, 1);                 // эквивалентно Point_move(p, 1, 1)
```

`MUT self` обязателен, если тело метода присваивает `self.<поле>` — та
же проверка, что и для обычных параметров (§5.1): без `MUT` присваивание
полю внутри метода — ошибка компиляции.

**Известное ограничение v0.1** (см. `docs/ROADMAP.md` и
`docs/SECURITY.md`): в отличие от обычных вызовов по имени
(`Call`), для `.method()` имя вызываемой функции зависит от
рантайм-типа получателя — структуры не имеют статического типа в v0.1
(нет `TypeAnnotation::Struct`). Поэтому compile-time проверка "получатель
обязан быть `var`-связанным, если метод требует `MUT self`"
(аналогичная `check_call_borrows` для обычных функций) **не
выполняется** для `.method()`-вызовов. Защита всё же действует на
уровне ТЕЛА метода: без `MUT self` присваивание `self.field` внутри
него отклоняется независимо от того, как был связан получатель на
месте вызова.

## 7. Типизация: аннотации типов (градуальная)

Аннотации полностью опциональны и проверяются отдельным проходом
(`src/typechecker/mod.rs`) ДО кодогенерации; без них переменная/параметр
остаются полностью динамическими — нулевая обратная несовместимость с
кодом, не использующим типы.

```
let x: int = 5;
fn add(a: int, b: int) -> int { return a + b; }

let y: int = "строка";       // ОШИБКА ТИПОВ на этапе компиляции
```

Допустимые имена типов: `int`, `float`, `bool`, `string`, `array`,
`closure`, `any`, `nil` — обычные ASCII-идентификаторы в позиции
аннотации (после `:` или `->`), НЕ новые SGA-ключевые слова (осознанное
решение — не трогать лексер/алфавит/VS Code расширение ради этой фичи).
`int` автоматически совместим с `float` (промоушен), `any` совместим со
всем. Типы элементов массива и сигнатуры замыканий НЕ проверяются (см.
ROADMAP — generics).

## 8. Модули (`IMPORT`)

```
// math.sga
fn square(x) { return x * x; }

// main.sga
IMPORT "math.sga";
print(square(5));   // 25
```

`IMPORT "путь";` — только на верхнем уровне программы (как и `FN
имя(...)`, см. EBNF ниже). Резолвится статически отдельным проходом
(`src/module_resolver.rs`) ДО семантического анализа: путь — относительно
директории файла, в котором встретился `IMPORT` (не текущей рабочей
директории процесса); top-level statement'ы импортированного файла
инлайнятся на место `IMPORT`. Циклические импорты — ошибка компиляции
с явным указанием цикла. Diamond-импорт (`A` импортирует `B` и `C`, оба
из которых импортируют `D`) — `D` инлайнится один раз (дедупликация по
канонiческому пути, pragma-once-подобная семантика), а не дублируется.

`IMPORT` доступен только при запуске через `sga::run_source_file`/`sga
run <файл>` (у файла есть путь на диске, от которого резолвятся
относительные импорты); `sga::run_source(текст)` без файлового контекста
отклоняет `IMPORT` явной ошибкой.

**Не реализовано** (см. ROADMAP): пакетный менеджер/реестр (`IMPORT`
работает только с локальными файловыми путями, не с именами пакетов),
пространства имён/алиасы (`IMPORT "math.sga" AS m;`), выборочный импорт
конкретных имён.

## 9. EBNF-грамматика (актуальная для v0.1)

```ebnf
program     = { top_level_statement } ;

(* IMPORT, именованный FN и STRUCT допустимы ТОЛЬКО на верхнем уровне *)
top_level_statement = import_stmt | fn_decl | struct_decl | statement ;

struct_decl = "STRUCT" ident "{" [ ident { "," ident } ] "}" ;

statement   = var_decl
            | expr_stmt
            | print_stmt
            | if_stmt
            | while_stmt
            | for_stmt
            | return_stmt
            | "BREAK" ";"
            | "CONTINUE" ";"
            | block ;

import_stmt = "IMPORT" STRING ";" ;
var_decl    = ("LET" | "VAR" | "CONST") ident [ ":" type_name ] "=" expr ";" ;
expr_stmt   = expr ";" ;
print_stmt  = "PRINT" "(" [ expr { "," expr } ] ")" ";" ;
if_stmt     = "IF" expr block [ "ELSE" (if_stmt | block) ] ;
while_stmt  = "WHILE" expr block ;
for_stmt    = "FOR" ident "IN" expr ".." expr block ;
fn_decl     = "FN" ident "(" [ param { "," param } ] ")" [ "->" type_name ] block ;
param       = [ "MUT" ] ident [ ":" type_name ] ;
type_name   = "int" | "float" | "bool" | "string" | "array" | "closure" | "any" | "NIL" ;
return_stmt = "RETURN" [ expr ] ";" ;
block       = "{" { statement } "}" ;

expr        = assignment ;
(* Левая часть присваивания валидируется на этапе разбора: ident,
   индексное выражение ("[...]") или доступ к полю ("." ident) — см.
   parser::parse_assignment. *)
assignment  = logic_or [ "=" assignment ] ;
logic_or    = logic_and { "OR" logic_and } ;
logic_and   = equality { "AND" equality } ;
equality    = comparison { ("==" | "!=") comparison } ;
comparison  = term { ("<" | ">" | "<=" | ">=") term } ;
term        = factor { ("+" | "-") factor } ;
factor      = unary { ("*" | "/" | "%") unary } ;
unary       = [ "-" | "NOT" ] postfix ;
(* "(" args ")" — общий постфиксный вызов: применим к ЛЮБОМУ primary,
   не только к идентификатору (IIFE на лямбде, f()(), arr[0](), ...).
   "." ident — доступ к полю struct, либо (если сразу за именем поля
   следует "(") вызов метода. Одиночный "." ОТЛИЧАЕТСЯ от ".." (диапазон
   FOR..IN) лукахедом на следующий токен — см. parser::next_is_dot и
   docs/MIGRATION_REPORT.md (конфликт грамматик, найденный при слиянии). *)
postfix     = primary { ("[" expr "]")
                       | ("(" [ expr { "," expr } ] ")")
                       | ("." ident [ "(" [ expr { "," expr } ] ")" ]) } ;
primary     = INT | FLOAT | STRING | "TRUE" | "FALSE" | "NIL"
            | ident [ "(" [ expr { "," expr } ] ")" ]   (* статический вызов по имени *)
            | ident "{" [ ident ":" expr { "," ident ":" expr } ] "}"  (* struct-литерал *)
            | "FN" "(" [ ident { "," ident } ] ")" [ "->" type_name ] block  (* замыкание-выражение *)
            | "[" [ expr { "," expr } ] "]"
            | "(" expr ")" ;

ident       = ASCII_LETTER { ASCII_LETTER | DIGIT | "_" } ;
```

Ключевые слова в продукции (`LET`, `IF`, ...) на практике в исходном
файле представлены SGA Private-Use-Area кодпоинтами — см.
`docs/SGA_ALPHABET.md`.
