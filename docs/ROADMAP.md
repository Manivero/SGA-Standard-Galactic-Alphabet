  КОМПИЛЯЦИИ, а не runtime, при непокрытом случае (осознанное решение,
  см. `docs/LANGUAGE_SPEC.md` §4.1). Компилируется целиком в уже
  существующие опкоды VM — ни один новый opcode не добавлен. Нет
  структурной struct-деструктуризации (см. "Не сделано" ниже).

  следующим же T009 (см. ниже).
- ✅ **`std/io`** (roadmap-приоритет 1, T009/M003, 2026-08-16):
  `read_file(path) -> string` — единственная функция `std/io` на момент T009
  (только чтение; запись добавлена позже — `write_file`, T015, см. ниже;
  удаление осознанно вне scope, см. "Не сделано"). Sandboxed:
  переиспользует ту же confinement-границу и
  проверку, что `IMPORT` (`module_resolver::is_within_root`/
  `compute_confinement_root`, обе сделаны `pub` специально для этого —
  единый источник истины) — абсолютные пути и выход за каталог входного
  файла программы через `..` отклоняются безусловно. Программы,
  запущенные через `run_source` (без файлового пути), получают понятную
  `RuntimeError` при вызове, а не тихо читают cwd процесса. Реализован НЕ
  в `runtime::call_builtin` (перехватывается в `Vm::call()` — нужен доступ
  к `Vm::sandbox_root`; с T012 так же устроен `args()`), см.
  `docs/VM_SPEC.md`.
- ✅ **`std/process`: `args()`** (M006, T012, 2026-10-11): `args() -> array`
  из string — аргументы командной строки программы (`sga run файл.sga арг1
  арг2`; всё после пути файла передаётся дословно, путь к самой программе
  в массив не входит; каждый вызов отдаёт новый массив). Параметры запуска
  вводятся как `RunOptions` (`run_source_with_options` /
  `run_source_file_with_options`); `Vm::new` не менялась — аргументы
  приходят через `Vm::set_args`. Не-UTF-8 аргумент в CLI теперь даёт
  понятную ошибку вместо паники. Пример — `examples/args.sga`.
- ✅ **`std/io`: `read_line()` / `read_stdin()`** (M006, T013, 2026-10-14):
  `read_line() -> string | nil` — следующая строка стандартного ввода без
  завершающего `\n`/`\r\n` (`nil` — ввод закончился, `""` — пустая
  строка); `read_stdin() -> string` — весь остаток ввода дословно (после
  него ввод исчерпан). Ввод — строгий UTF-8 (не-UTF-8 → `RuntimeError`, без
  подмены символов), чтение ленивое: `read_line()` потребляет одну строку и
  не ждёт конца ввода. Разбор — `src/stdin.rs` (чистые функции над
  `BufRead`); читатель принадлежит VM (`Vm::set_stdin`; `Vm::new` не
  менялась). Источник задаёт запускающая сторона: CLI `sga run` всегда
  подключает stdin процесса (`RunOptions::with_process_stdin()`),
  библиотека по умолчанию даёт ПУСТОЙ ввод, заданные байты —
  `RunOptions::with_stdin_bytes(..)`. Пример — `examples/stdin.sga`.
  Известные ограничения: размер ввода и длина строки не ограничены
  (`read_stdin()` держит ввод в памяти — на вводе 128 МиБ пик ≈259 МиБ, как
  у `read_file`; построчный цикл по тем же 128 МиБ — ≈11 МиБ), BOM в
  начале ввода остаётся данными первой строки.
- ✅ **`std/time`: `time_now_ms()` / `time_monotonic_ms()`** (M006, T014,
  2026-10-15): `time_now_ms() -> int` — календарное время: миллисекунды с
  1970-01-01T00:00:00Z (эпоха Unix, UTC) по системным часам (метка времени;
  следует за системными часами, поэтому может скакнуть при их переводе);
  `time_monotonic_ms() -> int` — миллисекунды, прошедшие с создания VM
  (`Vm::new`), по монотонным часам: не убывает и не зависит от перевода
  системных часов — для замера интервалов (разность двух вызовов; повторный
  `run` на той же VM продолжает отсчёт, а не обнуляет его). Оба результата —
  целые миллисекунды, округление вниз; время до 1970 и значение вне `int` —
  `RuntimeError`, без паники. Арифметика — `src/clock.rs` (чистые функции над
  инъектируемыми `SystemTime`/`Instant`, 11 unit-тестов); `time_now_ms`
  реализован в `runtime::call_builtin`, `time_monotonic_ms` — перехватом в
  `Vm::call()` (поле `Vm::started: Instant`; `Vm::new` не менялась).
  Разрешений и флагов CLI нет: чтение часов — не файловый и не сетевой I/O.
  Пример — `examples/time.sga`. Известные ограничения: часы настоящие и не
  подменяются встраивающим кодом (TD-014), поэтому программы со временем
  недетерминированы, а тесты проверяют свойства, а не точные значения;
  разрешение — 1 мс; нет `sleep` (ждать можно только активным циклом по
  часам), форматирования и разбора дат, часовых поясов.
- ✅ **`std/io`: `write_file(path, content)`** (M006, T015, 2026-10-18):
  создаёт или перезаписывает файл целиком, результат — `nil`. Запись
  **запрещена по умолчанию** — первая permission-граница SGA: разрешение
  выдаёт только запускающая сторона (`sga run --allow-write <файл>`, флаг
  обязан стоять ДО пути файла — всё после пути остаётся аргументами
  программы; `RunOptions::with_allow_write(true)` / `Vm::set_allow_write` в
  библиотеке), ни программа, ни `sga.toml`, ни окружение выдать его не
  могут. Граница пути — каталог входного файла, как у `read_file`: абсолютные
  пути, `..` и symlink'и наружу отклоняются; каталоги не создаются;
  symlink-цель отклоняется; содержимое пишется дословно. Реализация —
  `src/fs_sandbox.rs` (проверка пути и запись на реальной ФС, 20
  unit-тестов) + перехват в `Vm::call()`; `Vm::new` не менялась. **При
  реализации найден и исправлен дефект уже существовавшей защиты:** при
  запуске по голому имени файла (`sga run main.sga`, `sga run ./main.sga`)
  корень песочницы был ПУСТЫМ, и `read_file("../secret.txt")`,
  `IMPORT "../x.sga"` и чтение через symlink-каталог выходили за каталог
  программы; теперь корень никогда не бывает пустым, а лексическая проверка
  приводит пути к абсолютным (подробности — `docs/SECURITY.md`). Пример —
  `examples/write_file.sga` (`scripts/run_examples.sh` выдаёт разрешение
  только ему). Известные ограничения: разрешение — всё или ничего для всего
  каталога программы, включая её исходник и `sga.toml`; гонки между
  проверкой и записью, жёсткие ссылки, неатомарность, нет лимита размера
  (TD-016); нет append, mkdir, удаления, переименования и бинарных данных.
- ✅ **Optimizer** (roadmap-приоритет 4, T010/M004, 2026-08-18):
  constant folding + dead code elimination (DCE), `src/optimizer.rs` —
  AST→AST проход между `typechecker` и `codegen` (не между `codegen` и
  `vm`, как раньше предполагалось в `docs/COMPILER_SPEC.md` — осознанно
  пересмотрено при реализации). Арифметика переиспользует
  `vm::arith`/`vm::compare`/`vm::values_equal` (`pub(crate)`) — не
  дублируется, поэтому переполнение/деление на ноль НЕ сворачиваются и
  дают ту же `RuntimeError`, что и без оптимизатора. Недостижимый после
  DCE код по-прежнему проверяется семантикой/типами ДО удаления (проход
  идёт ПОСЛЕ `typechecker`) — ошибки в мёртвом коде не "прячутся".
  Инлайнинг функций — явно вне scope, см. "Не сделано" ниже.
- ✅ **Package Manager — path-зависимости** (roadmap-приоритет 6,
  T011/M005, 2026-10-10): `sga.toml` теперь не только генерируется
  (`sga init`), но и ЧИТАЕТСЯ — `src/manifest.rs`, ручной мини-парсер
  ТОЛЬКО секции `[dependencies]` (без внешнего `toml`-крейта, тот же
  принцип, что у `src/json.rs`). Единственная поддерживаемая форма —
  `имя = { path = "../каталог" }`; голая версия (`имя = "1.0"`) — явная
  `ImportError`, не молчаливая заглушка (у SGA нет реестра, версии без
  пути резолвить неоткуда). В коде: `IMPORT "pkg:имя/путь/к/файлу.sga";`
  — файл ищется внутри объявленного каталога пакета. Манифест ищется от
  каталога входного файла ВВЕРХ по дереву (ближайший побеждает, как
  `Cargo.toml`), а пути зависимостей считаются от каталога самого
  манифеста — поэтому раскладка, которую создаёт `sga init` (`sga.toml`
  в корне проекта, `src/main.sga` уровнем ниже), работает «из коробки».
  Пакет получает СОБСТВЕННУЮ confinement-границу
  (`module_resolver::is_within_root` переиспользуется, T009) — `..`
  внутри пакета не может выйти за его каталог. Транзитивные
  `pkg:`-импорты (пакет, импортирующий другой пакет) — явная ошибка, не
  поддерживаются в v0.1. Ошибки манифеста всплывают только при
  `pkg:`-импорте: программы без него ведут себя ровно как до T011. Без
  изменений в lexer/parser/AST (`pkg:` — обычная строка в
  `Stmt::Import`).
- ✅ **Расширенная стандартная библиотека**: `type_of`, `keys`, `range`,
  `sqrt`, `floor`, `ceil`, `abs`, `min`, `max`, `pow`, `str_split`,
  `str_contains`, `str_trim`, `str_starts_with`, `str_ends_with`,

## Сознательно НЕ реализовано (и почему)

### Бэкенды
- ❌ **LLVM-бэкенд** — нативная компиляция в машинный код требует
  привязки к `llvm-sys`/`inkwell`, корректную ABI/calling convention,
  работу с target triples под Windows/Linux/macOS × x86_64/ARM64. Это
  отдельный, многонедельный инженерный трек, требующий доступа к LLVM
  toolchain (которого нет в текущей sandbox-сети — см. ограничение
  сети в окружении разработки). Приоритет — следующий крупный milestone.
- ❌ **WebAssembly-бэкенд** — аналогично, отдельный codegen-таргет.
- Текущий бэкенд v0.1 — собственная байткод-VM (см. `docs/VM_SPEC.md`).
  Это осознанный, а не временный/"для вида" выбор: интерпретируемая VM
  даёт самый быстрый путь к **реально работающему** языку, позволяет
  внедрять safety-проверки (overflow/OOB/immutability) непосредственно в
  интерпретатор, и является стандартным первым шагом для новых языков
  (CPython, MRI Ruby, ранний Lua — все начинались как VM до AOT/JIT).

### Типы и язык
- ❌ `interface`/`trait` — ключевые слова зарезервированы в лексере и
  парсере, семантика не реализована. `struct` — см. "Сделано" выше
  (реализован при слиянии веток).
- ❌ `enum`, `map`, `set`, `tuple`, типобезопасный `optional` (`Option<T>`)
- ❌ `async`/`await`, потоки (`std/thread`, `std/async`)
- ❌ Generics / типизированные элементы массива — `array` как аннотация
  означает "это массив", но не "массив чего"; typechecker не проверяет
  типы элементов (см. `src/typechecker/mod.rs`). Структуры (см. выше)
  также типизируются как `any` — нет `TypeAnnotation::Struct` в v0.1.
- ❌ Инлайнинг функций (constant folding/DCE — ✅, см. "Сделано в
  v0.1.0" выше; инлайнинг явно вне scope T010, отдельная будущая задача)
- ❌ Реестр пакетов и версионирование — пакетный менеджер v0.1 умеет
  ТОЛЬКО path-зависимости (T011/M005, см. ✅ выше): `IMPORT "pkg:..."`
  резолвит лишь каталоги, объявленные в `sga.toml` как `{ path = "..." }`;
  транзитивные `pkg:`-зависимости не поддерживаются
- ❌ Статическая (compile-time) проверка call-site borrow'инга для
  `.method()`-вызовов (что получатель — `var`-связанное имя, если метод
  требует `MUT self`) — см. `docs/LANGUAGE_SPEC.md`, §6.

### Стандартная библиотека

## ЗАКРЫТО: дыра с границей immutability на вызовах функций (v0.1 → Ownership/Borrowing)

Была: **параметры функций всегда мутабельны независимо от immutability
аргумента на стороне вызова** (`src/vm/mod.rs::call`). Из-за этого
`let frozen = [1,2,3]; mutate(frozen);`, где `mutate` мутирует свой
параметр по индексу, реально менял данные `frozen`, несмотря на `LET`.

Выбран и реализован **Вариант B** (явные `MUT`-параметры, как Rust
`&mut`) — ближе к философии проекта, чем COW-вариант A:

- Параметры функций теперь **immutable по умолчанию**. Мутация
  (индексное присваивание, `push`, переприсваивание самого параметра)
  разрешена только если параметр явно объявлен `MUT`:
  `fn mutate(mut arr) { arr[0] = 99; }`.
- На месте вызова: передать `LET`/`CONST`-переменную в `MUT`-параметр —
  ошибка компиляции (`src/semantic/mod.rs`, проверка по сигнатуре
  функции). Передать `VAR`-переменную — разрешено.
- Проверка двойная (defense-in-depth, как и для прочих immutability-
  гарантий проекта): на этапе semantic-анализа **и** повторно в VM
  (`src/vm/mod.rs::call` теперь привязывает параметр в кадре вызова с
  флагом мутабельности из сигнатуры функции, а не всегда `true`).
- Новый SGA-токен `MUT` (U+EB4C U+EB54 U+EB53) — добавлен в
  `src/lexer/token.rs`, `tools/translit`, `docs/SGA_ALPHABET.md`,
  грамматику VS Code.
- Тест-характеристика дыры (`test_immutability_bypass_through_function_parameter_is_a_known_limitation`)
  обновлён и переименован в
  `test_immutability_bypass_through_function_parameter_is_now_fixed` —
  как и было анонсировано заранее, осознанно, не молча.

**Не реализовано** (честная граница этой версии, не "borrow-checker
Rust целиком"): нет lifetimes, нет анализа aliasing двух одновременных
заимствований одного значения, нет заимствований полей структур (структур
пока нет), `MUT` — это только проверка по одной паре "сигнатура функции
↔ аргумент вызова", а не общий граф владения по всей программе.
