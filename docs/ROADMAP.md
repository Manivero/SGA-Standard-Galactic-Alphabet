реализован совсем (без частичных заглушек, выдаваемых за рабочий код).

- ✅ **Замыкания / анонимные функции** (`FN(x) { ... }` как выражение):

- ✅ **Модули** (`IMPORT "путь.sga";`): резолвинг на верхнем уровне
  программы относительно директории файла, циклы импорта и
  diamond-импорты обрабатываются (см. `src/module_resolver.rs`,

- ✅ **Bytecode verifier**: `Vm::new` проверяет байткод (индексы пула

  исполнением, отклоняя повреждённые программы управляемой ошибкой
  вместо паники Rust.
- ✅ **Структуры** (`STRUCT TypeName { поля }`, roadmap-приоритет 8,
  частично — `match` всё ещё ❌): номинальный reference-тип, методы по
  конвенции `TypeName_method(self, ...)`, поля участвуют в
  Ownership/Borrowing на тех же правах, что и массивы. Перенесено из
  второй родительской ветки при слиянии — см. `docs/MIGRATION_REPORT.md`

  Известное ограничение: call-site borrow-checking для `.method()` не
  выполняется статически (см. `docs/LANGUAGE_SPEC.md`, §6, и
  `docs/SECURITY.md`) — структуры не участвуют в статической системе
  типов v0.1.
- ✅ **Расширенная стандартная библиотека**: `type_of`, `keys`, `range`,
  `sqrt`, `floor`, `ceil`, `abs`, `min`, `max`, `pow`, `str_split`,
  `str_contains`, `str_trim`, `str_starts_with`, `str_ends_with`,

## Сознательно НЕ реализовано (и почему)

### Бэкенды
- ❌ **LLVM-бэкенд** — нативная компиляция в машинный код требует
  привязки к `llvm-sys`/`inkwell`, корректную ABI/calling convention,
  работу с target triples под Windows/Linux/macOS × x86_64/ARM64. Это
  отдельный, многонедельный инженерный трек, требующий доступа к LLVM
  toolchain (которого нет в текущей sandbox-сети — см. ограничение
  сети в окружении разработки). Приоритет — следующий крупный milestone.
- ❌ **WebAssembly-бэкенд** — аналогично, отдельный codegen-таргет.
- Текущий бэкенд v0.1 — собственная байткод-VM (см. `docs/VM_SPEC.md`).
  Это осознанный, а не временный/"для вида" выбор: интерпретируемая VM
  даёт самый быстрый путь к **реально работающему** языку, позволяет
  внедрять safety-проверки (overflow/OOB/immutability) непосредственно в
  интерпретатор, и является стандартным первым шагом для новых языков
  (CPython, MRI Ruby, ранний Lua — все начинались как VM до AOT/JIT).

### Типы и язык
- ❌ `interface`/`trait` — ключевые слова зарезервированы в лексере и
  парсере, семантика не реализована. `struct` — см. "Сделано" выше
  (реализован при слиянии веток).
- ❌ `enum`, `map`, `set`, `tuple`, типобезопасный `optional` (`Option<T>`)
- ❌ `async`/`await`, потоки (`std/thread`, `std/async`)
- ❌ `match`-выражение
- ❌ Generics / типизированные элементы массива — `array` как аннотация
  означает "это массив", но не "массив чего"; typechecker не проверяет
  типы элементов (см. `src/typechecker/mod.rs`). Структуры (см. выше)
  также типизируются как `any` — нет `TypeAnnotation::Struct` в v0.1.
- ❌ Optimizer (constant folding, DCE, инлайнинг)
- ❌ Пакетный менеджер модулей (резолвинг по имени пакета, версии,
  реестр) — `IMPORT` резолвит только локальные файловые пути, см. ✅ выше
- ❌ Статическая (compile-time) проверка call-site borrow'инга для
  `.method()`-вызовов (что получатель — `var`-связанное имя, если метод
  требует `MUT self`) — см. `docs/LANGUAGE_SPEC.md`, §6.

### Стандартная библиотека
Реализовано: `len`, `push`, `to_string`, `to_int`, `to_float`, `type_of`,
`keys`, `range`, `sqrt`, `floor`, `ceil`, `abs`, `min`, `max`, `pow`,
`str_split`, `str_contains`, `str_trim`, `str_starts_with`,
`str_ends_with`, `str_replace`, `str_upper`, `str_lower`
(`src/runtime/mod.rs`). **Не реализовано**: `std/io` (файлы, помимо
`print`), `std/fs`, `std/net`, `std/http`, `std/crypto`, `std/time`,
`std/math` (кроме встроенных операторов), `std/json`, `std/random`,
`std/thread`, `std/async`, `std/process`, `std/collections` (кроме
базового `array`). Каждый из них требует системных вызовов/внешних
крейтов и отдельного дизайна безопасности (permission system для
sandboxed I/O) — нельзя честно "обозначить как готово" без реализации.

### Инструментарий
- ❌ `sga build` (нативный бинарник), `sga test` (тест-раннер с
  аннотациями), `sga lint`, `sga install`/`uninstall`/`doctor`/`update`
  — CLI явно сообщает "не реализовано", а не делает вид, что работает.
- ❌ Пакетный реестр и резолвер зависимостей для `sga.toml` — секция
  `[dependencies]` парсится в формате, но ничего не резолвит и не качает.
- ❌ VS Code: автодополнение, hover, go-to-definition, linting,
  diagnostics, formatter — это требует language server (LSP),
  отдельный процесс с собственным состоянием анализа; не входит в v0.1.
  Реализован только TextMate-грамматика для подсветки синтаксиса.
- ❌ Полноценный собственный TTF-шрифт, нарисованный специально для этого
  проекта — НЕ требуется: вместо этого подключён готовый сторонний шрифт
  **Fairfax HD** (OFL-1.1, см. `vscode-extension/fonts/NOTICE.md`),
  реально покрывающий зарегистрированный UCSUR-блок Standard Galactic
  (U+EB40–U+EB5F). Покрытие глифов проверено программно. Это сознательное
  инженерное решение: переиспользовать существующий открытый стандарт
  вместо параллельного изобретения своей PUA-схемы и рисования шрифта
  с нуля — см. `docs/SGA_ALPHABET.md`.

### Примеры из исходного запроса, не реализованные
JSON, HTTP, Async, Concurrency, CLI App, CRUD API — все требуют

## ЗАКРЫТО: дыра с границей immutability на вызовах функций (v0.1 → Ownership/Borrowing)

Была: **параметры функций всегда мутабельны независимо от immutability
аргумента на стороне вызова** (`src/vm/mod.rs::call`). Из-за этого
`let frozen = [1,2,3]; mutate(frozen);`, где `mutate` мутирует свой
параметр по индексу, реально менял данные `frozen`, несмотря на `LET`.

Выбран и реализован **Вариант B** (явные `MUT`-параметры, как Rust
`&mut`) — ближе к философии проекта, чем COW-вариант A:

- Параметры функций теперь **immutable по умолчанию**. Мутация
  (индексное присваивание, `push`, переприсваивание самого параметра)
  разрешена только если параметр явно объявлен `MUT`:
  `fn mutate(mut arr) { arr[0] = 99; }`.
- На месте вызова: передать `LET`/`CONST`-переменную в `MUT`-параметр —
  ошибка компиляции (`src/semantic/mod.rs`, проверка по сигнатуре
  функции). Передать `VAR`-переменную — разрешено.
- Проверка двойная (defense-in-depth, как и для прочих immutability-
  гарантий проекта): на этапе semantic-анализа **и** повторно в VM
  (`src/vm/mod.rs::call` теперь привязывает параметр в кадре вызова с
  флагом мутабельности из сигнатуры функции, а не всегда `true`).
- Новый SGA-токен `MUT` (U+EB4C U+EB54 U+EB53) — добавлен в
  `src/lexer/token.rs`, `tools/translit`, `docs/SGA_ALPHABET.md`,
  грамматику VS Code.
- Тест-характеристика дыры (`test_immutability_bypass_through_function_parameter_is_a_known_limitation`)
  обновлён и переименован в
  `test_immutability_bypass_through_function_parameter_is_now_fixed` —
  как и было анонсировано заранее, осознанно, не молча.

**Не реализовано** (честная граница этой версии, не "borrow-checker
Rust целиком"): нет lifetimes, нет анализа aliasing двух одновременных
заимствований одного значения, нет заимствований полей структур (структур
пока нет), `MUT` — это только проверка по одной паре "сигнатура функции
↔ аргумент вызова", а не общий граф владения по всей программе.

## Предлагаемый порядок следующих шагов

Пункты 1 (Type System), 2 (Ownership/Borrowing) и 3 (Modules) из
исходного приоритета, а также замыкания/анонимные функции (изначально
не входившие явно в 10-пунктовый приоритет) — выполнены, см. секции
выше и `docs/MIGRATION_REPORT.md`. Дальше по тому же приоритету:

1. `std/io` (чтение файлов) + `std/json` (т.к. часто нужны вместе).
2. Optimizer (constant folding, DCE) — пункт 4 исходного приоритета.
3. WASM-бэкенд, затем LLVM-бэкенд (пункт 5 исходного приоритета).
4. Package Manager — резолвер зависимостей/реестр для `sga.toml`
   (пункт 6) — отдельная задача от уже реализованного локального
   `IMPORT` по файловым путям.
5. Остальной `std` (net/http/crypto/thread/async).
6. LSP для VS Code (пункт 8).
7. Async Runtime (пункт 9).
8. `match`-выражение — нужен для идиоматичного `std/collections`
   (`struct` уже реализован, см. "Сделано в v0.1.0" выше).
9. Полноценный borrow-checker для замыканий (множественные одновременные
   заимствования, mutable upvalues через `Rc<RefCell<Value>>` per-переменная,
   а не захват по значению) — см. `runtime::Value::Closure`.
