# SGA Programming Language

**SGA** — самостоятельный язык программирования, ключевые слова которого
закодированы алфавитом зачарований Minecraft (Standard Galactic Alphabet).
Файлы исходного кода имеют расширение `.sga`.

> **Статус: v0.1.0 — реальный, рабочий, но честно ограниченный по объёму
> релиз.** Это не концепт и не псевдокод: лексер, парсер, семантический
> анализатор, проверка типов, кодогенератор, резолвер модулей и
> байткод-VM реально реализованы на Rust, компилируются без единого
> warning'а (`cargo clippy` — 0 предупреждений, `cargo fmt --check` —
> чисто) и проходят 386 тестов (`cargo test`).
> Поддерживаются градуальная статическая типизация, Ownership/Borrowing
> (`MUT`-параметры), замыкания, многофайловые программы (`IMPORT`,
> включая path-зависимости из `sga.toml`), структуры (`STRUCT`) с
> методами и расширенная стандартная библиотека (32 встроенные
> функции). Чего здесь **нет** — честно перечислено в
> [`docs/ROADMAP.md`](docs/ROADMAP.md): нативного бэкенда (LLVM/WASM),
> полноценного `std` (сеть, http, crypto, async, threads), пакетного
> реестра и языкового сервера для VS Code. Это инженерно правдивая отсечка
> объёма, а не попытка скрыть недостающее.

## Почему именно так

SGA — это не "Python с другим синтаксисом" и не шифратор. Ключевые слова
(`LET`, `FN`, `IF`, `WHILE`, ...) физически закодированы не ASCII-буквами,
а отдельными Unicode-кодпоинтами из официально зарегистрированного блока
**Standard Galactic** (U+EB40–U+EB5F, Under-ConScript Unicode Registry).
Сам алфавит — конструированная письменность Tom Hall для Commander Keen
(1990), которую Minecraft переиспользовал в 2011 как шрифт зачарований —
подробная история и проверенные источники в
[`docs/SGA_ALPHABET.md`](docs/SGA_ALPHABET.md).

Идентификаторы, числа, строки и операторы — обычный UTF-8/ASCII: это
осознанный выбор, иначе языком было бы невозможно пользоваться без
специальной клавиатуры.

**Руны зачарования реально отображаются**: в `vscode-extension/fonts/`
подключён готовый шрифт **Fairfax HD** (Kreative Software, лицензия
SIL OFL-1.1) — после однократной установки в систему `.sga`-файлы в
VS Code показывают настоящие иероглифы, а не пустые прямоугольники.

## Быстрый старт

Требуется Rust ≥ 1.75 (`rustc`, `cargo`).

```bash
cd sga
cargo build --release
./target/release/sga run examples/hello.sga
```

```
Hello, SGA Programming Language!
```

Создать новый проект:

```bash
./target/release/sga init my-project
./target/release/sga run my-project/src/main.sga
```

### Зависимости (path)

Пакетный менеджер v0.1 — только локальные path-зависимости (реестра
пакетов нет). В `sga.toml` проекта:

```toml
[dependencies]
mylib = { path = "../mylib" }
```

В коде: `IMPORT "pkg:mylib/utils.sga";` — файл `../mylib/utils.sga`
подключается как обычный модуль. `sga.toml` ищется от каталога
запускаемого файла вверх по дереву, а путь зависимости считается от
каталога самого манифеста, поэтому проект, созданный `sga init`,
работает без дополнительной настройки. Подробности и ограничения —
[`docs/LANGUAGE_SPEC.md`](docs/LANGUAGE_SPEC.md), §8.1.

### Аргументы программы

Всё, что стоит после пути файла, программа получает через builtin
`args()` — массив строк (путь к самой программе в него не входит):

```bash
./target/release/sga run examples/args.sga один "два слова" --флаг
```

Аргументы передаются дословно, в том числе похожие на флаги. Строки SGA —
UTF-8, поэтому не-UTF-8 аргумент отклоняется с понятной ошибкой. Из Rust:
`RunOptions::new().with_args(..)` и `sga::run_source_file_with_options`.

### Стандартный ввод

`read_line()` возвращает следующую строку стандартного ввода без
завершающего `\n` или `\r\n`, а когда ввод закончился — `nil`; пустая
строка `""` — это настоящая пустая строка, а не конец ввода.
`read_stdin()` забирает весь остаток ввода дословно:

```bash
printf 'Тема: привет\nАвтор: Аня\n\nТекст письма' | ./target/release/sga run examples/stdin.sga
```

Ввод читается лениво — ровно столько, сколько запросила программа, так что
интерактивный ввод с терминала работает построчно. Ввод должен быть
валидным UTF-8, иначе программа получит понятную ошибку выполнения (символы
молча не подменяются). Размер ввода не ограничен: `read_stdin()` держит
весь ввод в памяти, а цикл по `read_line()` — нет. Из Rust ввод по
умолчанию пуст; задать его можно через
`RunOptions::new().with_stdin_bytes(..)`, подключить stdin процесса —
`with_process_stdin()`.

### Время

`time_now_ms()` возвращает календарное время — целое число миллисекунд с
1970-01-01T00:00:00Z (эпоха Unix, UTC) по системным часам: метка для логов и
для сравнения с другими системами. `time_monotonic_ms()` — миллисекунды,
прошедшие с создания VM, по монотонным часам: значение не убывает и не
зависит от перевода системных часов, поэтому интервалы измеряют как разность
двух вызовов:

```bash
./target/release/sga run examples/time.sga
```

Разрешений и флагов не нужно — это чтение часов, а не файловый ввод-вывод.
Часы настоящие и из Rust не подменяются, так что вывод программ, читающих
время, меняется от запуска к запуску; нет `sleep` (ждать можно только циклом
по часам), форматирования дат и часовых поясов.

### Запись файлов

`write_file(путь, содержимое)` создаёт файл или перезаписывает его целиком и
возвращает `nil`. **Запись запрещена по умолчанию** — её разрешает только тот,
кто запускает программу, флагом `--allow-write`, который обязан стоять ДО пути
файла:

```bash
./target/release/sga run --allow-write examples/write_file.sga
```

Без флага `write_file` завершает программу понятной ошибкой с подсказкой,
ничего не создав. Сама программа, `sga.toml` и переменные окружения выдать
себе разрешение не могут; `--allow-write` ПОСЛЕ пути файла — обычный аргумент
программы (виден в `args()`) и ничего не разрешает. Если путь файла начинается
с `-`, напишите `./-имя.sga` или поставьте перед ним `--`.

Путь, как у `read_file`, относителен каталогу запускаемого `.sga`-файла и не
может выйти за его пределы: абсолютные пути, `..` наружу и symlink'и, ведущие
наружу, отклоняются. Каталоги `write_file` не создаёт (родительский каталог
должен существовать), существующий symlink в роли цели отклоняется, текст
пишется дословно (перевод строки в конце — на вашей совести). Разрешение
действует на ВСЮ программу — включая импортированные модули и
`pkg:`-зависимости — и на весь каталог программы, в том числе на её собственный
исходник и лежащий рядом `sga.toml`: запускайте с `--allow-write` только
программы, которым доверяете. Из Rust:
`RunOptions::new().with_allow_write(true)` и `sga::run_source_file_with_options`.
Известные ограничения (гонки между проверкой и записью, жёсткие ссылки,
неатомарность, нет лимита размера) — в [`docs/SECURITY.md`](docs/SECURITY.md).

### Как писать код, если ключевые слова — не ASCII?

Пишите обычными ASCII-мнемониками (`let`, `fn`, `if`, ...) в файле
`*.sga.src`, затем превратите его в настоящий `.sga` с реальными
SGA-кодпоинтами:

```bash
cargo build -p sga-translit --manifest-path tools/translit/Cargo.toml
./tools/translit/target/debug/sga-translit my_program.sga.src my_program.sga
./target/release/sga run my_program.sga
```

Этот же конвейер использован для генерации всех файлов в `examples/` —
читаемые исходники лежат в `examples-src/*.sga.src`.

## Структура репозитория

```
sga/
  src/
    lib.rs        точки входа run_source()/run_source_file() (+ `*_with_options`, `RunOptions`) — полный пайплайн
    main.rs       CLI (run [--allow-write]/init/fmt/version/...)
    lexer/        лексер (распознаёт SGA-кодпоинты как ключевые слова)
    parser/       рекурсивный спуск, токены -> AST
    ast/          определения узлов AST (включая Lambda/Import/типы)
    semantic/     неизменяемость, Ownership/Borrowing, область видимости замыканий
    typechecker/  градуальная статическая типизация (опциональные `: тип`)
    module_resolver.rs  резолвинг IMPORT (циклы, diamond-дедупликация, pkg:-зависимости)
    manifest.rs   минимальный парсер секции [dependencies] из sga.toml
    optimizer.rs  constant folding + dead code elimination (AST -> AST)
    json.rs       json_stringify/json_parse без внешних зависимостей
    stdin.rs      разбор стандартного ввода для read_line()/read_stdin() (строгий UTF-8)
    clock.rs      арифметика часов для time_now_ms()/time_monotonic_ms() (миллисекунды)
    fs_sandbox.rs проверка пути и запись файла для write_file() (песочница каталога программы)
    codegen/      AST -> байткод (OpCode/Chunk), backpatching для циклов
    vm/           стековая VM, bytecode verifier, защита от stack overflow
    runtime/      Value (+ Closure), Chunk/OpCode/FunctionDef, встроенные функции
    sga_alphabet.rs  таблица SGA <-> Unicode PUA
  tools/translit/ инструмент транслитерации ASCII-мнемоник в реальный SGA
  examples/        готовые .sga программы (настоящие SGA-кодпоинты)
  examples-src/    их же читаемые ASCII-исходники
  tests/           интеграционные + модульные тесты (cargo test)
  docs/            спецификации
  vscode-extension/ расширение VS Code (синтаксис, сниппеты)
  scripts/         build.sh, run_examples.sh
```

## CLI

| Команда                         | Статус                                            |
|----------------------------------|---------------------------------------------------|
| `sga run [--allow-write] [--] <файл.sga> [арг...]` | ✅ реализовано — компиляция + исполнение на VM; `арг...` → builtin `args()`, stdin → `read_line()`/`read_stdin()`; `--allow-write` (только ДО пути файла) разрешает `write_file()` |
| `sga init [путь]`                | ✅ реализовано — создаёт `sga.toml` (с примером path-зависимости) + `src/main.sga` |
| `sga fmt <файл.sga>`             | ✅ частично — печатает разобранный AST            |
| `sga build`                      | ❌ запланировано (нативный бэкенд), см. ROADMAP    |
| `sga test/lint/install/...`      | ❌ запланировано, см. ROADMAP                      |
