# Contributing to SGA

## Сборка и тесты

```bash
cargo build               # компилятор + VM
cargo test                # 152 теста (110 интеграционных + 12 модульных + 26 unit-тестов лексера + 4 unit-теста json)
cargo build --manifest-path tools/translit/Cargo.toml   # инструмент транслитерации
```

Перед PR: `cargo build` должен завершаться без единого warning'а
(`cargo build 2>&1 | grep warning` — пусто), `cargo test` — все тесты
зелёные.

## Куда смотреть, если хочешь добавить фичу

| Хочу добавить... | Начинай с |
|---|---|
| Новую конструкцию синтаксиса (например `match`) | `src/lexer/token.rs` (если нужно ключевое слово) -> `src/ast/mod.rs` -> `src/parser/mod.rs` -> `src/semantic/mod.rs` -> `src/codegen/mod.rs` -> `src/vm/mod.rs` |
| Новый встроенный тип (`map`, `set`, ...) | `src/runtime/mod.rs::Value` + везде, где `match value { ... }` бьёт по типу (компилятор подскажет через exhaustiveness check) |
| Новую встроенную функцию | `src/runtime/mod.rs::call_builtin` + `is_builtin` |
| Изменение в таблице SGA-алфавита | `src/sga_alphabet.rs` — **и** `tools/translit/src/main.rs` (дублирует таблицу намеренно, чтобы инструмент оставался независимым однобинарным CLI; при изменении синхронизируй оба файла и `docs/SGA_ALPHABET.md`) |

## Правила honesty, принятые в этом проекте

Эти правила были применены при первоначальной разработке и обязательны
для дальнейших вкладов:

1. **Не объявляй фичу готовой, если она не покрыта тестом или ручной
   проверкой через `cargo run -- run <файл>`.** Если фича частично
   реализована — это явно отражается в `docs/ROADMAP.md`, а не в
   комментарии `// TODO` внутри кода, который легко не заметить.
2. **Любое утверждение про безопасность в `docs/SECURITY.md` должно быть
   подтверждено тестом.** Если нашёл реальную уязвимость/краш при
   разработке — фиксируй её в коде, а не только описывай как
   "ограничение". (Пример: `MAX_DISPLAY_DEPTH` в `src/runtime/mod.rs` —
   реальный баг с stack overflow на самореференцирующихся массивах был
   найден и исправлен, не просто упомянут.)
3. **Не копируй >30% синтаксиса существующего языка.** При добавлении
   конструкции — сверься с философией в `docs/LANGUAGE_SPEC.md`, §1.

## Структура коммитов

Один логический шаг пайплайна — один коммит, где возможно (например,
"добавить токен MATCH" отдельно от "добавить парсинг match-выражения"),
чтобы `git bisect` оставался полезным при поиске регрессий в компиляторе.
